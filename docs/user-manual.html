Orientation

What this system is

The Payroll System replaces the four-sheet Excel workbook that used to carry Next Media payroll. It does the same job — a mid-month allowance run and a month-end salary run for each business unit — but rests on two changes that remove the fragile parts of a spreadsheet:

  • One employee master record. Every screen, pay run and bank file reads a person’s name, Staff ID and bank details from a single record. Nothing is re-typed, so the name-spelling drift between sheets cannot happen. Matching is always by Staff ID, never by name.
  • An automated statutory engine. PAYE and NSSF are computed from versioned, effective-dated tax tables — not typed in by hand. Every payslip shows which band was used.

Totals are computed by grouping on the business-unit field, so adding or removing one employee can never quietly break a total somewhere else.

The model in one glance

A pay run is one cycle for one month. Calculating it builds one line per active employee. Each line moves through a fixed lifecycle:

Draft→ Calculated→ Reviewed→ Approved→ Disbursed

The Head of Human Capital prepares and calculates the run; the Chief People Officer reviews it; the Chief Audit Officer approves it; the Chief Finance Officer disburses it. Each step must be a different person, and a bank file can only come from an approved run.

The operating cycle

The monthly rhythm

For each business unit, two runs go out each month against largely the same people:

Run typeTimingWhat it paysStatutory?
Expense Allowance Mid-month (around the 15th) Gross allowance, less recurring deductions such as SACCO and Fuel/Advance No PAYE or NSSF
Salary Month-end (around the 27th) Basic salary plus taxable earnings, less PAYE, NSSF and recurring deductions PAYE + NSSF computed automatically

The run’s title is built from its pay date — for example PAYROLL FOR THE MONTH ENDED 27 OCTOBER 2026. You never type it.

The run lifecycle

Every run moves forward through these states. It can be reopened from Reviewed or Approved back to Calculated; a Disbursed run is final.

StateMeaningWho moves it on
DraftCreated, not yet calculated.Head of Human Capital — Calculate
CalculatedLines built from the master + statutory engine. Safe to recalculate.Chief People Officer — Mark reviewed
ReviewedThe Chief People Officer has checked it. Blocked while any line has a variance.Chief Audit Officer — Approve
ApprovedSigned off. The bank file and statutory returns unlock.Chief Finance Officer — Mark disbursed
DisbursedPaid. Loan balances have been reduced. Final.—
Notifications Each step emails the next officer in the chain: calculating notifies the Chief People Officer, reviewing notifies the Chief Audit Officer, approving notifies the Chief Finance Officer, and disbursing notifies the Head of Human Capital and Chief Finance Officer.
For HR

The employee master

Everything a pay run needs about a person lives on one record. Keep it current and the runs take care of themselves.

Add an employee

Employees ▸ + New employee
  1. Fill the Identity block. Staff ID and Position are mandatory; add Email so payslips can be sent, and TIN / NSSF number so the person appears correctly on statutory returns.
  2. Set Placement — business unit, department, engagement type (Payroll staff, Independent contractor, or Wage staff).
  3. Enter the Pay bases: monthly gross salary (the base for the Salary run) and monthly expense allowance (the base for the Expense Allowance run). Either can be zero.
  4. Enter a payment method — a bank account number (numeric, 8–20 digits) or a mobile-money number. At least one is required.
  5. Set the join date and save. The person is now picked up by any run whose pay date is on or after that date.

Edit an employee

Employees ▸ open the record ▸ Edit

Change anything except the identity of a paid line already in a run. A leaver is handled by setting a Left date — the record flips to Inactive and drops out of future runs, but history is kept. Never delete a person.

Attach a recurring deduction or earning

Employees ▸ open the record ▸ + Deduction / + Earning
  1. Choose the code (SACCO, Food, Hire purchase, Acting allowance… see the code list).
  2. Enter the amount taken each run.
  3. For a deduction, choose Apply on — Both runs, Salary run only, or Expense Allowance run only. This lets you take, say, a SACCO contribution on the month-end run only for one person even though the SACCO code itself allows both. You cannot pick a run the code does not support (the form rejects it).
  4. Set recurrence to Recurring (every matching run) or One-off.
  5. For a loan code — Hire purchase or Fuel/Advance — enter the Opening balance. The instalment is capped at the balance, the balance falls each time a run is disbursed, and the deduction switches itself off when it reaches zero.
  6. Optionally set Effective from / to dates to fence the deduction to a period. Save. Use edit / remove on the row to change it later.
Which run picks it up A deduction is taken on a run only when both the code allows that run type and the deduction’s Apply on setting includes it. Each code is flagged for the Salary run, the Expense Allowance run, or both — Penalty is salary-only, Fuel/Advance is expense-only.

Bulk update from a spreadsheet

Employees ▸ Bulk update

Use this to change salaries, allowances, status or bank details for many people at once.

  1. Click Download template CSV for a file keyed by staff_id with current values.
  2. Edit only the columns you want to change — any column you leave out is untouched. Updatable columns: monthly_gross_salary, monthly_expense_allowance, status, position, email, tin, nssf_number, bank_name, bank_account_number.
  3. Upload it and click Preview changes. You get a row-by-row from → to table plus a count of rows that will update, are unchanged, or have errors (unknown Staff ID, a non-numeric amount).
  4. Check the preview, then Apply. Nothing is written until you confirm.

Onboard new joiners from a spreadsheet

Employees ▸ Onboard CSV

Same preview-then-confirm flow, for creating people. Required columns: staff_id, full_legal_name, position, business_unit (code or name), date_joined, and a payment method (bank_account_number or mobile_money_number). Every row is validated exactly as the on-screen form would — a duplicate Staff ID, an unknown business unit or a bad date becomes an error row and is skipped.

Mandatory fields & validation

For the Head of Human Capital

Preparing a cycle

Create a pay run

Pay runs ▸ New pay run
  1. Choose the run type — Expense Allowance or Salary.
  2. Choose the scope. Runs are normally scoped to one business unit, so pick the unit. Two shortcuts are also available: Every business unit creates one Draft run per unit in a single step, and All business units creates a single group-wide run.
  3. Pick the period (month and year). The pay date defaults to the 15th or the 27th; override it if the actual payment date differs.
  4. Add a note if useful and click Create run. You land on the run in Draft. Only one run of each type can exist per unit per month.
One unit at a time Each unit’s run is calculated, reviewed, approved and disbursed on its own — the Pay runs list has a business-unit filter, and the run title carries the unit name.

Calculate

Run page ▸ Calculate

Calculating builds one line per employee who is active on the pay date, from their pay base, their attached earnings and deductions, and — for a Salary run — PAYE and NSSF from the tax table effective on that date. It is idempotent: run it again any time before approval and it rebuilds cleanly. Loan balances are only projected here; they are not touched until the run is disbursed.

Read the run

The run page shows, in order:

  • Headline totals — employees, gross, net pay, and a count of variance lines.
  • vs the previous run — gross / PAYE / net deltas against the last run of the same type, plus who joined and who left since then.
  • Totals by business unit — grouped, with a grand total. These add up by construction; there are no hand-pointed formulas.
  • Lines — every employee, with the PAYE band shown on hover. A line with a missing or invalid account is tagged acct.

Fix a variance

Every line carries a check: gross − (net + statutory + deductions) must be 0. A non-zero value almost always means a deduction is larger than the pay it is taken from.

  1. Open the flagged line from the banner at the top of the run.
  2. Fix the underlying data — reduce the deduction amount, or set its Effective to date, or adjust the pay base on the employee record.
  3. Return to the run and Recalculate. The banner clears when every line balances.
Review is gated Mark reviewed stays disabled until zero lines have a variance. This is deliberate.

Edit or delete a run

Run page ▸ Edit / Delete

You can change the pay date and notes while the run is Draft or Calculated. If you move the pay date on a calculated run, recalculate — the statutory figures are tied to it. A run can be deleted only while Draft or Calculated; once approved it is locked.

Hand it to the Chief People Officer

When the run balances, the Head of Human Capital’s job is done — the Chief People Officer takes it from Calculated. The Mark reviewed button only appears for that officer.

Review · Approve · Disburse

The sign-off chain

Three officers act after the run is calculated, and each must be a different person — the system rejects a self-review, a self-approval and a self-disbursement.

Review — Chief People Officer

Run page ▸ Mark reviewed

Only a Calculated run with zero variance lines can be marked reviewed, and the reviewer must not be the person who prepared the run. This records that the Chief People Officer has checked the run and hands it to the Chief Audit Officer. Your name and the time are stamped on the run automatically.

Approve — Chief Audit Officer

Run page ▸ Approve

Only a Reviewed run can be approved, and the approver must be a different person from the reviewer — the system rejects a self-approval. Your name and timestamp are captured. Approval unlocks the bank file and the statutory returns.

The audit trail

Audit trail in the sidebar (Chief Audit Officer only)

A single, read-only timeline of every create, change and delete across employees, pay runs, recurring deductions & earnings, business units and statutory tables — most recent first, with the person who made each change and, for an update, exactly which fields moved and their old and new values. Filter it by record type, action (created / updated / deleted), who made the change, and a start date.

This is not a separate log kept alongside the system — it reads the same change history every screen and the admin already write to, just merged into one place and given plain-English labels. Nothing on this page can be edited.

Disburse — Chief Finance Officer

Everything from here — the bank file, the statutory returns, payslip emails and Mark disbursed — belongs to the Chief Finance Officer, who must not be the officer who approved the run.

Generate the bank file

Run page ▸ Bank file
  1. Choose the scope — the whole group or a single business unit.
  2. Review the preview. Records with a missing or malformed account number are listed and block the download until fixed on the employee record (then recalculate).
  3. Click Download CSV. The file has a numbered row per payee — name, Staff ID, bank, account, amount — and a TOTAL row. Amounts are plain numbers so the bank’s import can parse them.

Statutory returns

Run page ▸ PAYE return CSV / NSSF return CSV

Available from a calculated Salary run. The PAYE return lists TIN, Staff ID, name, unit, gross, chargeable income, PAYE and band, with a total. The NSSF return lists NSSF number, gross, the 5% employee and 10% employer amounts and the 15% total, with totals. Both are structured for import, not a fixed portal template — confirm the layout your filing tool expects.

Payslips

Every payslip is branded with the employee’s business unit — its logo and name in the header. Upload a unit’s logo in the admin (Business units › the unit › Logo); units without one show the Next Media mark.

Mark disbursed

Run page ▸ Mark disbursed

Do this once payment has actually gone out. This is the single point where loan balances (Hire purchase, Fuel/Advance) are reduced by the instalment taken in this run; a loan that reaches zero switches itself off. The run is now final.

Reopen a run

If something needs changing after review or approval, use Reopen to send the run back to Calculated. Fix the data, recalculate, and take it through review and approval again. A Disbursed run cannot be reopened.

Reference

Rates, codes & screens

Uganda PAYE — monthly, resident individuals

The engine applies the table that is active and effective on the run’s pay date. The figures below are the current URA bands.

Monthly chargeable income (UGX)Tax on that income
0 – 235,000Nil
235,001 – 335,00010% of the amount above 235,000
335,001 – 410,00020% of the amount above 335,000, plus 10,000
410,001 – 10,000,00030% of the amount above 410,000, plus 25,000
Above 10,000,000The 30% band, plus a further 10% of the amount above 10,000,000

The extra 10% above UGX 10,000,000 makes the effective top rate 40%. PAYE is charged on gross pay; the employee’s NSSF contribution is not deducted first.

Proposed FY2026/27 A draft table with a UGX 335,000 tax-free threshold is pre-loaded but inactive. An administrator activates it once assented; runs already calculated keep the table they were calculated against.

NSSF

5% is deducted from the employee’s gross. 10% is an employer cost shown for information, not deducted from pay. Together they are the 15% remitted to NSSF. This applies to every employer under the NSSF Act 2022.

When something is off

Troubleshooting

“Mark reviewed” is greyed out
Cause One or more lines have a non-zero variance.
Fix Open each flagged line from the banner, reduce the oversized deduction (or fence it with effective dates), then recalculate.
“Download CSV” on the bank file is disabled
Cause Some payees have a missing or malformed account number.
Fix The page lists them. Correct the account (numeric, 8–20 digits) on each employee record, recalculate the run, and re-approve if needed.
I can’t approve the run
Cause Either the run is not in Reviewed, or you are the person who reviewed it.
Fix The Chief Audit Officer signs off, and must be someone other than the Chief People Officer who reviewed it — segregation of duties is enforced.
I can’t edit or delete a run
Cause It is already Approved or Disbursed.
Fix Use Reopen (from Reviewed or Approved) to return it to Calculated. A disbursed run is final.
PAYE looks wrong after a rate change
Cause The run was calculated against the previous tax table.
Fix Recalculate. Runs already finalised deliberately keep the version they were calculated with.
An employee is missing from the run
Cause They are not active on the pay date — the join date is after it, or a leaver date is before it.
Fix Correct the dates on the record and recalculate.
An Expense Allowance line shows a negative net
Cause Recurring deductions add up to more than the allowance.
Fix Lower the deduction, or set an effective-to date, or raise the allowance on the record.
“Email all payslips” skipped someone
Cause That person has no email address on file (or a zero net).
Fix Add the address to the record, then email that one payslip from its page.
A new joiner arrived mid-cycle
Fix Add them (or bulk-onboard) with a join date on or before the pay date, then recalculate the run.
Terms

Glossary

Pay run
One cycle for one business unit for one month — a run type, a scope, a period and a pay date.
Run scope
The business unit a run covers. A run can also be group-wide (all units), but the normal practice is one run per unit.
Run type
Expense Allowance (mid-month) or Salary (month-end).
Line
One employee’s calculated pay within a run: gross, statutory, deductions, net.
Variance
The per-line check gross − (net + statutory + deductions). Must be zero.
Chargeable income
The taxable part of gross that PAYE bands are applied to.
Statutory
PAYE and the employee NSSF contribution — the legally required deductions.
Disbursement
Marking a run paid; the moment loan balances are reduced.
Business unit
A Next Media entity (NBS, Sanyuka, Next Radio…). A field on the employee, not a block of rows.
Engagement type
Payroll staff, Independent contractor, or Wage staff.
Recurring / one-off
Whether an attached earning or deduction repeats every matching run or applies once.
Loan (deduction)
A deduction with an opening balance that falls each disbursement and stops at zero (Hire purchase, Fuel/Advance).
Effective-dated
A tax table or component that applies only from a given date; older runs keep the version they used.
Segregation of duties
Every step of the four-officer chain — prepare, review, approve, disburse — must be a different person from the step before it. The system enforces this.
Four-officer chain
Head of Human Capital prepares → Chief People Officer reviews → Chief Audit Officer approves → Chief Finance Officer disburses.
Audit trail
The Chief Audit Officer's read-only timeline of every create/change/delete across the system, with the acting user and a field-level diff. See §6.
Master record
The single employee record every screen, run and export reads from.
